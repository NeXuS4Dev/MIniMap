# История версий

Версии ниже восстановлены по истории git. В репозитории нет git-тегов, поэтому номера сгруппированы как логические этапы разработки.

## 1.2.6 - 2026-08-02

- **Найден и устранён настоящий корень «мёртвой миникарты».** Дамп 1.2.5 показал невозможное: рантайм-флаг включён, постфикс камеры исправно тикает, ванильный радар здоров — а захвата радара нет, и все стражи отсекали выполнение с причиной `runtimeDisabled`. Виновник: проверки вида `MinimalMinimap.Instance == null`. `Instance` — это Unity-компонент (MonoBehaviour); если игра уничтожает его GameObject, Unity делает объект «почти null» (т.н. fake-null): управляемый код, поля и методы продолжают работать (конфиг пишется, F2 переключает, логи идут), но проверка `== null` навсегда возвращает истину. Все стражи мода опирались на эту проверку, поэтому логика молча отключалась при полностью живом патче. Тем же артефактом объясняются и «фантомные переключения конфига» из дампов 1.2.2–1.2.4: значение читалось через уже мёртвый Instance.
- **Весь runtime-стейт переведён на простые статики; `Instance` полностью исключён из логики.** `ConfigEnabled` стал статическим (ConfigEntry — обычный C#-объект, не умирает вместе с Unity-объектом), добавлена единая проверка `IsEnabled()` с принципом «при сомнениях — включено»: стражи больше не могут молча погасить мод из-за чужого сбоя. `Instance` остался только для диагностики.
- **Диагностика доказывает диагноз.** При первом тике патча в лог пишется «карточка примет»: жив ли Unity-объект плагина (`pluginInstanceAlive` = смокинг-ган, если объект мёртв) и абсолютные пути выполняемых сборок (ловит двойную загрузку старой копии dll из другого каталога). F6-дамп дополнительно печатает `pluginInstanceAlive`, `dataHash`, идентификаторы Assembly всех классов мода и список всех Harmony-владельцев, патчивших `ManualCameraRenderer.Update` (видно вмешательство других модов).

## 1.2.5 - 2026-08-02

- **Сторож камеры радара на собственном компоненте (`MinimapKeepAlive`).** Дампы 1.2.4 показали парадокс: рантайм-флаг включён, постфикс жив, все условия стражей проходят — а захвата радара нет (`shipRadarRuns=0`). Теперь включение камеры выполняет маленький компонент на отдельном GameObject: его `LateUpdate` идёт ПОСЛЕ всех `Update` в кадре, поэтому принудительное включение гарантированно побеждает ванильное выключение камеры за пределами видимости монитора — и не зависит от того, тикает ли вообще `ManualCameraRenderer.Update`.
- **Микроскоп над стражами постфикса.** Для экземпляра `mapScreen` отдельно считаются тики обновления (`mapScreenTicks`) и причина отсева (`mapScreenGate`: `runtimeDisabled` / `mapCamera==null` / `cam!=mapCamera` / `passing`). Идентификация корабельного радара дополнительно дублируется через `ReferenceEquals(__instance, StartOfRound.Instance.mapScreen)` — даже если проверка `cam==mapCamera` врёт, логика радара всё равно сработает.
- F6-дамп печатает также счётчики сторожа (`keepAliveTicks`, `keepAliveEnforces`, `lastEnforce`).

## 1.2.4 - 2026-08-02

- **Состояние вкл/выкл отвязано от BepInEx-конфига на время сессии.** Дампы 1.2.3 показали невозможное: оверлей виден (`overlay=active`) при `configEnabled=False`, а счётчик захвата радара (`shipRadarRuns`) оставался нулевым даже после F2 «ON». Причина: значение `Enabled` в конфиг-хранилище BepInEx фантомно менялось без нажатия F2 (hot-reload файла и гонки его записи — каждый F2 немедленно сохраняет файл на диск, а BepInEx может перечитывать его асинхронно) и молча гасило постфикс камеры. Теперь сессией управляет собственный флаг мода (`RuntimeEnabled`), инициализируемый из конфига при запуске; `F2` переключает его и сохраняет выбор в конфиг для следующих запусков.
- **Любое расхождение конфиг-файла логируется.** Каждый раз, когда значение `Enabled` в хранилище меняется (в т.ч. без нашего участия), в лог пишется предупреждение с текущим рантайм-состоянием.
- **Контрольное сообщение о захвате радара.** При первом успешном удержании камеры радара пишется `Ship radar control engaged` — сразу видно, что живой режим реально включился.
- **F6-дамп перечисляет все `ManualCameraRenderer` в сцене** (включая неактивные): имя объекта, активность, включённость компонента и камер. Плюс явно печатает `runtimeEnabled` и `configEntry (DRIFT!)` при рассинхроне.

## 1.2.3 - 2026-08-02

- **Миникарта теперь включена по умолчанию.** Настройка `Enabled` по умолчанию была `false`, поэтому на свежем профиле (или после пересоздания конфига) мод молча бездействовал: оверлей скрыт, камера радара гасла при выходе из корабля — это выглядело как «замершая/мёртвая миникарта», а F3 при этом заблокирован. Теперь значение по умолчанию `true`; `F2` по-прежнему переключает, выбор сохраняется. (Если в вашем конфиге уже записано `Enabled = false`, один раз нажмите `F2` в игре.)
- **Радар центрируется на вас в начале каждой жизни.** Раньше при включённой фиксации цели (по умолчанию) авто-центрирование срабатывало только после смерти/возрождения, поэтому после высадки миникарта могла следить за другим игроком. Ручное переключение по `F3` по-прежнему не перебивается до конца жизни.
- **F6-дамп стал самодиагностикой.** Теперь в начале строки выводит состояние самого мода: включён ли (`configEnabled`), виден ли оверлей (`overlay`) и счётчики вызовов патча камеры (`patchRuns`/`shipRadarRuns`/`lastShipRun`) — по ним сразу видно, работает патч или нет.
- Нажатия `F2`/`F3` записываются в лог BepInEx.
- Камера удерживается включённой через оба поля (`cam` и `mapCamera`).

## 1.2.2 - 2026-08-02

- **Исправлена замершая миникарта после посадки.** Если флаг `overrideCameraForOtherUse` («инфо-экран орбиты») зависал включённым уже после приземления, ванильный код радара полностью пропускался — камера переставала следовать за целью и картинка замирала статичным кадром (и переключение цели по F3 визуально «не работало»). Пока идёт раунд, мод теперь принудительно снимает этот флаг; на орбите инфо-экран не трогается.
- **Исправлен краш дампа по F6.** Чтение приватного поля игры напрямую вызывало `FieldAccessException` (Mono проверяет доступность членов в рантайме, несмотря на публичность в референс-сборках). Поле теперь читается через reflection, а дамп обёрнут в try/catch.

## 1.2.1 - 2026-08-02

- **Миникарта больше не замирает статичным кадром.** Текстура миникарты теперь непрерывно привязывается к актуальному `targetTexture` камеры радара: раньше привязка делалась один раз при подключении, и если игра меняла/пересоздавала RenderTexture на переходах (экран информации о луне, посадка, позднее подключение), миникарта навсегда оставалась с замершим старым кадром.
- Добавлена отладочная клавиша **F6**: выводит в лог BepInEx полное состояние радара (`inShipPhase`, `overrideCameraForOtherUse`, состояние камер, привязку текстуры и т.д.) — для диагностики «замерзшей» или пустой миникарты.

## 1.2.0 - 2026-08-02

Совместимость с **Lethal Company v81** (проверено по v81-сборке игры; работает и на v80).

- **Мод стал полностью клиентским.** Удалена регистрация сетевого prefab'а через Unity Netcode (`NetworkPrefabPatch`) — мёртвый код, который только создавал риск рассинхрона с сервером. Теперь мод ничего не отправляет по сети и безопасно работает в ванильных лобби.
- **Исправлена поломка на v80/v81.** В игре метод `ManualCameraRenderer.updateMapTarget` стал корутиной (`IEnumerator`). Старый префикс, блокировавший её вызов, приводил к `ArgumentNullException` в `StartCoroutine(null)` при любом внешнем переключении цели (например, когда другой игрок переключает радар с терминала). Блокировка вынесена на входные точки: `SwitchRadarTargetForward`, `SwitchRadarTargetAndSync` и `SwitchRadarTargetClientRpc`; сама корутина больше не патчится.
- **Устойчивость к обновлениям игры.** `Harmony.PatchAll()` заменён на применение патчей по одному: если в будущей версии игры переименуют метод, отвалится только связанная фича, а не весь мод (с объяснением в логе BepInEx).
- Имя цели на подписи радара (`mapScreenPlayerName`) обновляется при переключении цели модом — в v81 игра делает это только внутри своей корутины.
- Добавлена защита от выхода `targetTransformIndex` за границы списка целей (выход игрока из лобби и т.п.).
- Камера радара явно удерживается включённой: с v80 игра рендерит монитор с пониженным FPS и только пока он виден игроку.
- `FindObjectsOfType<TerminalAccessibleObject>()` теперь кешируется и обновляется раз в секунду вместо вызова каждый кадр.
- Добавлены проверки на готовность HUD при создании оверлея и ленивая повторная привязка текстуры радара.
- **Сборка переведена на SDK-style проект и NuGet.** Больше не нужен локальный путь к игре (`D:\SteamLibrary\...`): игровые сборки v81 подтягиваются из `LethalCompany.GameLibs.Steam 81.0.5-ngd.0`. Сборка: `dotnet build -c Release` (нужен .NET 8 SDK вместо .NET Framework 4.8). Добавлен готовый workflow автосборки для GitHub Actions (`build-workflow.example.yml` → `.github/workflows/build.yml`).
